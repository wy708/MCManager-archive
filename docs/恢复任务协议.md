# 新目录恢复任务协议

中央服务已提供恢复任务、归档占用、受限下载和结果确认协议。宿主 0.4.0 已接通实际下载、新目录解包、完整清单和原回执重连，见 [验证范围](testing.md)。网页向导也已接通，三种方式、工作进程中断和原回执重连均通过联合实服验证，见 [验证范围](testing.md)。下面的协议夹具与实际游戏验证分别记录。

## 身份和方式

| 方式 | 目标身份 | 采集处理 |
| --- | --- | --- |
| `DISABLED` | 保留备份来源的档案 UUID | 关闭采集，隔离旧缓存，供独立检查 |
| `CONTINUE` | 同一期 UUID | 保留中央新历史，原事件按原身份幂等补传；必须使用同一期执行端和当前有效的采集凭据 |
| `FORK` | 请求内新建一期，返回新的 UUID | 旧缓存隔离；只为这次新建的目标配置新凭据，不复制来源凭据 |

继续原一期要求档案仍在记录中，开始、下载及确认结果时游戏处于 `STOPPED` 维护状态。已封存档案可独立检查或创建新一期，不会被协议悄悄解封。独立检查与新一期可以由管理员明确分配到其他执行端，只有那个任务才获得读取该归档的许可。

网页只提交一个 NFC 规范化的新目录名，不提交磁盘路径；允许字母、汉字、数字、下划线和短横线，拒绝路径、保留设备名及重复名称。目标父目录由宿主本地 `restoreDirectory` 配置决定，执行程序拒绝已存在的目录，不覆盖原游戏。取消或失败保留新档案和诊断记录，不自动删除档案历史。

## 状态和占用

`QUEUED → CLAIMED → RUNNING → READY`。READY 只表示主机提交了与原任务一致的文件准备回执，返回的 `worldRuntimeVerified` 始终是 `false`；实际启动、世界和背包验证仍是独立的验收。

- 请求 UUID 与原参数一起去重。创建新一期、归档锁定和排队在同一事务完成；重复请求不会再次创建一期。
- 同一执行端的制作备份与恢复尝试相互排斥。旧宿主省略 `restoreEnabled` 时默认为 `false`，不能领取恢复任务，原有备份流程继续工作。
- 领取租约为 120 秒。CLAIMED 过期可重新领取；RUNNING 过期进入 UNCERTAIN，禁止自动解包第二次。
- 停服维护中的活跃恢复同样占用运行实例；另一个 runId 不能因为游戏状态是 STOPPED 就接管仍有效的恢复。
- 取消已开始的任务只请求停止，等待执行端报告；不确定结果须先核对本地目录，再由管理员记录失败或取消。原完成回执可通过恢复确认接口重新提交，但不能改变恢复身份、来源摘要、目标 UUID、目录名或文件数。
- QUEUED、CLAIMED、RUNNING 和 UNCERTAIN 都占用原归档。手动删除返回冲突，自动轮换候选也排除它；任务可靠结束后才释放占用。原归档摘要、版本和统计截止说明在任务中固定保存。

## 管理接口

所有操作使用管理员会话，修改须 CSRF 校验。

| 方法 | 路径 | 含义 |
| --- | --- | --- |
| GET | `/api/restores?serverId=&page=0&size=20` | 来源或目标属于所选服务器的恢复记录 |
| GET | `/api/restores/{id}` | 固定来源、统计衔接、状态与诊断 |
| POST | `/api/backups/{id}/restores` | 创建任务，字段见下 |
| POST | `/api/restores/{id}/cancel` | 请求取消 |
| POST | `/api/restores/{id}/resolve` | 仅 UNCERTAIN，`outcome=FAILED|CANCELLED` 及非空 `note` |

创建字段为 `requestId`、`hostId`、`mode`、`destinationName`、`note`、`forkName`、`forkStartDate`。只有 FORK 填写新一期名称和日期，其他方式须为空。创建时执行端必须已经明确报告恢复能力；归档必须已完成校验。

## 执行端接口

沿用 `/api/host/**` 独立无状态鉴权。心跳增加 `restoreEnabled`；它是执行端的能力声明，不是中央已经验证该程序可恢复游戏的证明。

| 方法 | `/api/host/v1` 后路径 | 用途 |
| --- | --- | --- |
| POST | `/restores/claim` | `runId`、稳定 `requestId`；没有任务返回 204 |
| GET | `/restores/{id}` | 只能查看分配给自己的任务 |
| POST | `/restores/{id}/start`、`/renew` | `runId`、`attemptId` |
| GET | `/restores/{id}/content` | 只读原归档，头为 `X-Host-Run`、`X-Restore-Attempt` |
| POST | `/restores/{id}/collector` | 当前尝试确认目标采集配置，不返回凭据 |
| POST | `/restores/{id}/report` | 失败、取消或不确定结果及固定错误码 |
| POST | `/restores/{id}/ready`、`/recover` | 原始文件准备回执或中断后的原回执确认 |

下载只允许 RUNNING 的有效尝试，不开放普通备份下载权限。发送前重算原文件摘要；流中至多读取 1 MiB 一段，并按字节预算或一秒间隔复核凭据、实例、租约和取消状态。零字节读取不重置预算，快速传输也使用同一检查路径。权限变化会终止后续传输，客户端必须拒绝不完整长度或摘要不一致的文件。

`collector` 的字段为 `runId`、`attemptId`、`collectorToken`。CONTINUE 验证执行端本地现用的原档案凭据，不轮换正在使用的原凭据。FORK 只允许在新建目标没有其他凭据时安装候选，且重试必须保持同一个值；后台仅保存 SHA-256，不在任务 JSON 或数据库中保存/返回原文。宿主后续实现使用本地持久化的随机值，或按如下方式稳定派生：

`targetServerId + "." + base64url(HMAC-SHA256(hostToken, "mcmanager-restore:" + jobId + ":" + targetServerId))`

取消、失败或撤销执行端会撤销尚未 READY 的新一期凭据；如果管理员已经另行轮换为新凭据，不会误删替换值。已 READY 的新一期与来源执行端独立，不因来源执行端撤销而停用。

文件准备回执包含 `runId`、`attemptId`、`restorationId`、`sourceBackupId`、`targetServerId`、`mode`、`destinationName`、`sha256` 和原 `fileCount`。启用采集的方式还必须已经通过目标凭据确认；这些字段不会被当成实际游玩回执。

## 本模块验证范围

Flyway V10 增加恢复记录、租约、能力声明与占用索引。新增 **36 项 H2/PostgreSQL 恢复测试**覆盖三种身份、重复创建、路径拒绝、租约过期、维护实例排他、取消与撤销、归档占用、凭据摘要和更换保护、受限下载及快速传输。完整后端 **182 项全部通过**，既有桌面/手机网页 **25 项回归通过**。原始日志为忽略的 `.tools/restore-protocol-full-final.log` 与 `.tools/restore-protocol-browser-regression.log`。

`node backup/qa/verify-restore-protocol.mjs` 对实际 Docker Nginx / API / PostgreSQL 创建独立协议夹具，上传真实校验器认可的合成归档，再以宿主凭据下载并核对完整摘要；验证占用防删除、取消等待回报、FORK 幂等及失败后撤销新凭据。它不执行解包、不启动游戏，明确记录 `realGameplay=false`、`hostFilesystemRestored=false`。`--check-persistence` 在容器重建后再次核对记录与实际归档字节。


宿主与网页阶段已完成本地新目录约束、持久化工作进程和向导，并通过固定版本真实 BDS 的世界、背包及统计衔接验证。整台宿主故障、异机网络与外部数据库仍是后续系统运维验收范围。
