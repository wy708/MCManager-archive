# 服务器运行状况

采集器 0.37.0、MCP 0.6.2（无需为此次更新替换）、平台数据库 V30。

## 怎么查看

后台侧边栏进入“运行状况”，选择服务器。页面每 15 秒读取一次，可查看最近 1 小时、6 小时、24 小时或 7 天。网页地址 `/runtime?server=服务器UUID` 可收藏并刷新。

AI 调用 `get_server_runtime`，提供 `serverId`，可选 `hours`（1–168，默认 24）。需要该服的 `STATS_READ` 权限；不需要新端口，也不会向游戏下发扫描任务。

## 记录内容

| 数据 | 含义 |
| --- | --- |
| 整机 CPU | 所有程序合计的 CPU 占用及逻辑核心数；首个差分样本为空，超过 64 个逻辑核心暂不返回占用率 |
| 整机磁盘 | 有盘符的固定磁盘总量、可用空间；不是磁盘读写速度 |
| 整机网络 | 已启用物理网卡接收/发送字节每秒合计；不重复相加虚拟网卡，缺少可用接口时为空 |
| 游戏流畅度 TPS | 采样期间推进的游戏 tick 数除以经过时间，最多显示 20；低于 18 提醒 |
| 最长游戏帧间隔 | 两次 tick 之间的最长等待，包括尚未结束的等待；不是单帧执行耗时 MSPT |
| 游戏进程 CPU | 游戏进程消耗的 CPU 时间占整台机器全部逻辑核心的比例，不是整机总占用 |
| 游戏进程内存 | 工作集（实际驻留内存）；API 另外保留私有内存大小 |
| 主机内存 | 物理内存总量、剩余可用量 |
| 在线人数 | 游戏线程最近观察到的在线人数；游戏卡住时不能当作实时人数 |
| 启动与时间 | 采集启动编号、采集运行时长、采样时间、平台接收时间、最近 tick 时间 |

页面先显示整台运行游戏的 Windows 主机，再显示游戏进程；不是 平台主机 的资源数据。此功能随游戏插件采样，停服后不继续监控主机。

游戏线程只更新计数和时间；Windows 主机及进程资源信息在上传线程读取，通常约 10 秒一次。没有额外扫描实体、区块或方块。网络请求耗时和断线可能延长采样间隔，因此不能保证严格每 10 秒到达。

首次 CPU 采样、系统接口读取失败均返回空值。明细保留 30 天，后台每小时清理过期数据；最长一次查询 7 天。曲线在 1–6 小时内按 10 秒、24 小时内按 1 分钟、更长范围按 10 分钟汇总。TPS 按时间加权，CPU/内存/网络速率取采样平均，人数/帧间隔取最大值；缺口不补成零。

## 状态边界

超过 45 秒没有新采样显示“运行数据中断”，不能单凭这一项认定游戏崩溃。上传线程仍有响应、但游戏至少 5 秒没有 tick 时显示“游戏长时间未推进”。正常停止时最终记录写入本地持久队列，下次启动补传；停止后在补传前可能先显示数据中断。插件停止不等于游戏进程已经退出。

采样按启动编号和序号去重，迟到的旧样本不覆盖较新的状态。网络断开期间运行采样不保证全部保留；玩家行为仍使用原有持久队列。区块数、实体数和真正的 MSPT 当前未采集，也不会把观察到的卡顿直接归因给某个玩家。

## 方块坐标与 AI 分析

`get_recent_activity` 和 `wait_for_activity` 的成功放置、拆除记录现在保留 `position: {x, y, z}`，同时保留玩家、`dimension`、`occurredAt` 和方块种类。已有支持坐标的采集器（包括 0.33.0）在平台升级后上传的新记录即可保存坐标；不必为此单独停服。

AI 可以分页读取行为，按同一玩家、维度、相邻坐标和时间分析活动。例如大量连续挖掘可作为“可能在挖通道”的依据，不能当成已确认目的。这里只记录采集到的行为，不是完整建筑语义识别。升级前未保存的历史坐标返回 `null`，不能从玩家当前位置反推或补造。

## 更新

游戏服更新采集器 0.37.0 后开始整机 CPU、磁盘和网络采样；旧版进程和主机内存记录仍可查询。有人在线时可把压缩包放在独立待更新目录；等正常停服、进程退出后再覆盖插件文件，保留原配置和 `data`。MCP 在机器人电脑更新到 0.6.2 后重启对应 MCP 连接。具体步骤见 [程序安装与更新](程序安装与更新.md)。
