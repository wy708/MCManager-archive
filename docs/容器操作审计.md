# 容器操作记录

采集器 0.30.0 的 BDS 1.26.61.1 配置新增容器操作记录。MCP 0.5.0 新增 `get_container_history`，原有 30 个工具保留。后端数据库迁移 V19 创建独立审计表，不把容器记录混入物品使用次数。

## 能回答什么

例如：“查纯生存服主世界 100、64、-200 的箱子，昨天谁打开过，有什么物品变化？”AI 必须先确定服务器、维度和完整坐标，再调用查询工具。双箱任意一半坐标都可以查询同一份转移记录。

|记录|证据与边界|
|---|---|
|OPEN 打开|观察到玩家服务器端已打开的容器界面；每游戏 tick 检查一次，时间是观察时间，极短打开关闭可能漏记。不能据此断言拿走物品。|
|TRANSFER 物品变动|游戏 `tryCommitActionResults` 实际成功后，比对同一容器槽位的物品类型和数量。记录玩家与变动前后数值。拒绝或回滚的请求不算玩家转移。不能直接断言物品最终进入背包，也不能据此判断盗窃。|
|PLACE / BREAK 放置与破坏|复用现有放置、挖掘完成检查，额外保存容器坐标和玩家。不是仅记录操作请求。|
|CHANGE 无法归属的变化|打开的容器每 20 tick 采样，以及玩家交易前检查到的其他变化。玩家字段为空；可能来自漏斗、命令或其他插件，不能指认附近玩家或最近打开者。记录的是两次观察之间的净变化，不保证完整自动化流水。|

支持普通箱子、陷阱箱、木桶、潜影盒、漏斗、发射器、投掷器、熔炉类、酿造台及合成器的方块容器。末影箱、实体容器、无人打开的自动化容器不在本版覆盖范围。同类型同数量但附魔、名称、耐久等附加信息变化暂不记录。旧 1.26.51 采集配置不声明支持这项能力。

记录从升级后开始；之前未采集的操作不能追溯。未加载区域不扫描、不强制加载，不遍历世界方块。已上传的历史在玩家和游戏服离线时仍可查询。

## MCP 与权限

需要 Agent 对目标档案拥有 `WORLD_READ` 权限，使用现有平台端口，不新增端口。

```json
{
  "serverId": "目标档案 UUID",
  "dimension": "minecraft:overworld",
  "x": 100,
  "y": 64,
  "z": -200,
  "radius": 0,
  "limit": 50
}
```

`from`、`to` 接受带时区的时间；默认最近 7 天，一次最多 31 天。`radius` 是三维方形范围，最大 16 格；精确箱子查询使用 0。`playerKey` 可选。结果按入库顺序倒序，实际时间看 `occurredAt`，断线补传可能较晚入库。翻页保留返回的 `from/to`，把 `nextBefore` 原样作为 `before`；游标是字符串。`hasMore=false` 表示本次范围查完，不表示全历史完整。

接口：`GET /api/agent/servers/{serverId}/container-history`。事件经过采集凭据绑定、字段验证、档案日期验证、事件去重及数据库事务；服务器权限检查在查询前后执行。旧事件的规范化哈希保持不变，不破坏断线补传。

## 存储与性能

记录保存在平台 PostgreSQL 的 `container_audit` 和 `container_audit_locations` 表，位置索引用于查询。当前不自动清除此表；数据库备份包含这些记录。游戏文件备份与此独立。

游戏线程只做有界观察和内存入队。只检查在线玩家当前界面；每个容器最多 256 槽，最多保留 128 个观察基线。提交时读取当前操作容器前后状态，不扫描世界。磁盘和 HTTP 使用原来的后台工作线程；上传批次按大小拆分，限制在 1 MiB 内。积压或观察异常进入现有采集缺口诊断，不伪装为完整记录。
