# 整机监控与扩展图表（2026-11-10）

采集器 0.37.0，Windows x64 BDS 1.26.61.1；平台数据库 V30。地图 1.0.3+mcmanager.6 和 MCP 0.6.2 此次不变。

## 整机先于游戏进程

后台“运行状况”先展示运行游戏的 Windows 主机：全部程序合计 CPU、物理内存使用、固定磁盘容量/剩余空间、物理网卡收发速率。下方保留游戏进程 CPU、驻留内存、TPS、最长帧间隔和在线人数，方便比较。

- 系统接口在上传线程调用，不在游戏线程扫描，不持有游戏 tick 计数锁执行系统读取。
- 约 10 秒采样，附在原有上传批次，不新建采样上传轮询。
- CPU、网速需要前后两个样本；首次、接口失效、计数重置时不补零。超过 64 个逻辑核心暂不提供整机 CPU，避免跨处理器组误计。
- 网络仅合计已启用硬件网卡，排除虚拟/VPN 网卡重复流量；没有满足条件的接口则为空。不是每个程序的网络速度。
- 磁盘为带盘符固定卷的总量/可用空间，不是磁盘 I/O 或健康状态。
- 这是游戏插件附带的主机采样，不是独立常驻监控程序。游戏或插件停止后停止采样；旧数据明确标注中断，不能当作实时值。
- 旧采集器数据仍接收，旧样本去重哈希兼容。新指标从升级后开始，不补造历史记录。

## 性能与统计质量

原七图共用原接口，新七图首次打开时才读取 `/api/statistics/exploration/extended`，之后切换复用同一结果。每份结果按服务器、日期、时区缓存两分钟，最多八份；每次只渲染当前图表，页面不自动重查大汇总。日期最多 31 天，运行明细只保留 30 天。

扩展查询使用已有每日统计、工程阶段、备份和运行样本，不新增游戏行为采集。玩家最多 500 位（按在线时长排序），时间轴最多 300 条工程/备份事件，超出明确提示；旭日沿用原贡献接口的覆盖边界。查询在只读事务中执行，缓存等待不持有数据库连接，单条 SQL 8 秒超时。

运行箱线图直接对记录样本计算分位数，缺样本不补零；它不代表每一帧的执行时间。没有活动记录也不能认定没有活动。工程重叠时贡献分别计入，部分种植/收获同时属于放置/挖掘。

## 游戏服更新

1. 下载 `MCManager-Collector-1.26.61.1-0.37.0.zip`，先存放在游戏目录外。
2. 有人在线时不要覆盖；正常 `stop`、等待退出并关闭执行端。
3. 备份游戏目录 `plugins/archive-collector` 的原 DLL 和清单。
4. 将压缩包中的 `plugins` 合并到**游戏目录**，仅覆盖 DLL 与 `manifest.json`；保留 config、data、世界和框架。
5. 使用原来的 `03-start.cmd` 启动，确认采集器 0.37.0，随后后台会出现新主机指标。

不需要重新安装框架或逐版升级，也不用为此更新 MCP、地图、端口或游戏联网配置。

## 验证边界

后端测试覆盖新字段验证、旧采样重传、服务器隔离、只读账号、分位数与缓存。浏览器脚本 `scripts/verify-exploration.mjs` 使用真实隔离后端与合成游戏记录检查十四图、手机布局、共享请求，并将当前 Windows 机器的真实系统采样上传再读取核对。采集 DLL 针对 1.26.61.1 编译；这些检查不代替真实游戏机升级后的持续运行验证。
