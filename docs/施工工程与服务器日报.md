# 施工工程与服务器日报

适用于采集插件 0.32.0、MCP 0.6.1（38 个工具）及含 V22 数据库迁移的平台。

## 游戏内操作

普通玩家可使用这些命令，不需要改动服务器的作弊设置：

1. 站在第一个角，执行 `/project pos1`。
2. 站在同一维度的第二个角，执行 `/project pos2`。
3. 执行 `/project create 工程名`。名字带空格时加双引号。
4. 完成时执行 `/project finish 工程名`；需要继续时执行 `/project resume 工程名`。
5. 修改范围：重新选两个点，再执行 `/project range 工程名`。

`/project retry` 使用同一请求编号重试最近一次操作。收到“结果尚未确认”时用它，避免把同一次范围修改重复执行成多个阶段；重启插件后这份本地重试记录不会保留，应先查看后台工程状态。

两点只限定 X/Z 水平矩形，边界包含在内，记录所有高度。换维度会清除之前的选点；工程不能直接改到另一个维度。同一玩家、同一服务器下工程名唯一，不同玩家可同名。按名字操作只查找操作者自己创建的工程。

## 贡献与封存

- **所有玩家**在范围内成功放置、拆除方块都会分别计入贡献，创建者身份只限制管理操作。
- 记录开始前的历史行为不会补算。材料图例统计的是放置/拆除次数，不是背包消耗，也不是建筑当前存量；活塞、爆炸、自动机器等未归属到玩家的变化不冒充施工贡献。
- 重叠工程各自计数；服务器日报用原始服务器统计，不重复累加工程数据。
- 修改范围会封存原阶段，按新范围开始下一阶段。累计贡献保留此前阶段；每个旧阶段都能查看自己的范围、地图和累计统计。
- 完成时冻结**平台已收到的统计和最近保存的地图**。尚在采集端排队、网络断开时未上传的事件不会再补进已封存阶段；建议先等采集端上传正常、后台统计追上后完工。
- 地图并不是完成瞬间的完整世界备份。未采集的区域保留空白；封存后不会补图。继续施工开启新阶段，旧阶段仍只读。
- 下界使用现有地图的 64 层洞穴视图；所有高度参与贡献，不代表二维图片能显示所有楼层。

## 公开地图与后台

工程链接为 `/projects/工程UUID`，无需登录。只返回当前选择阶段的范围裁剪图片和工程统计，不向访问者提供整服地图瓦片。页面支持放大、滚动、历史阶段、中文方块图标和玩家贡献图表。公开贡献包含游戏昵称，不包含 XUID、QQ 号码或凭据。

管理员从“施工工程”按服务器查看、创建或管理工程；后台管理员可以覆盖创建者管理限制。管理员创建的工程不能由普通玩家冒领。

“服务器日报”可选择日期，显示已记录玩家、在线/活跃时间、建造与挖掘、物品使用、聊天次数、死亡次数、七天趋势和工程阶段变化。日期按平台统计时区划分，默认昨天；补传数据会更新日报。没有数据不代表没有行为。日报不自动向 QQ 发消息，由接入的机器人按需求读取并回复。

## AI / DSH 接入

原有 31 个 MCP 工具保留，新增：

- `list_construction_projects`：服务器工程列表。
- `get_construction_project`：当前或历史阶段、贡献、材料和公开链接。
- `create_construction_project`：绑定玩家创建工程。
- `update_construction_range`：按工程名修改范围。
- `complete_construction_project`：按工程名完成。
- `resume_construction_project`：按工程名继续。
- `get_server_daily_report`：读取服务器日报。

读取工程需要 `WORLD_READ`；日报需要 `STATS_READ`。创建、修改、完成和继续需要 **`PROJECT_WRITE` + `QQ_BIND`**，并先完成 QQ 与游戏角色绑定。后台“AI 助手”可为对应服务器勾选“管理绑定玩家的施工工程”。不要给 AI 猜测 QQ 号码：`qqId` 必须来自 DSH 收到的可信 OneBot 事件发送者，而不是群消息正文中声称的身份。

例如：“把我的林间小屋范围改成主世界 (100, 200) 到 (180, 260)。”AI 先确定服务器，再调用修改工具，保留相同 `requestId` 处理网络失败重试。完成后的工程要先继续，才能修改范围。

## 部署

没有新增公网端口。地图服务添加私网 `POST /internal/project-map`，既有公网地图代理只接受 GET/HEAD，不转发这个请求。后端配置固定映射：

```text
MCM_PROJECT_MAP_SOURCES=服务器UUID=http://mipmap:8000
```

多服务器用逗号分隔，各 UUID 指向自己的内部 MipMap 实例；不能由公开请求指定任意地址。地图每轮最多处理 20 个阶段，默认一分钟轮询，输出最长边 1024 像素，每次最多读取 1024 个已有瓦片；巨大范围的部分采样会明确标注。操作不会遍历或强制加载游戏区块。

V20 将工程、阶段、统计和 PNG 快照保存在平台数据库中，数据库备份会包含它们。插件通过已有采集接口上传逐次放置/拆除坐标，没有新增游戏监听端口。更新采集 DLL 时保留配置与 data 目录；DSH 更新 MCP 源文件后需重启该 MCP 进程。

方块图例素材为现有 MipMap 官方 Bedrock 资源生成的默认俯视图，许可证保存在 `frontend/public/project-icons/LICENSE.md`。未知或模组方块可能只有名称和次数，没有图标。

管理员可在后台删除任意工程，确认后清除全部工程阶段、地图和贡献统计，公开链接失效；服务器原始行为数据和总统计保留。旧创建请求会被标记为已删除，补传或网络重试不会把工程自动建回来。AI 和游戏命令不提供删除功能。
