# 世界存档备份（备份程序 0.7.0）

新版游戏主机备份程序默认只保存 `server.properties` 中 `level-name` 指定的当前世界。包含该世界的地形、建筑、容器内容、原版玩家存档，以及世界目录内部的资源和配置文件。

不包含服务端程序、插件、采集插件的待上传/已上传记录、日志、其他世界、服务端根目录下的全局资源包或平台数据库。插件自行保存的背包/经济等数据也不在世界备份内。已有的整服备份仍可校验、下载和恢复。

## 更新现有接入包

1. 等玩家下线后正常停止游戏，并关闭网页控制台执行端。
2. 将 `MCManager-World-Backup-0.7.0.zip` 解压到原接入包目录，与原 `03-start.cmd` 同级，不是游戏的 `plugins` 目录。
3. 运行 `更新世界备份.cmd`，看到“世界存档备份 0.7.0 已安装”后运行原 `03-start.cmd`。
4. 网页“备份中心 → 对应服务器 → 备份任务”的游戏主机版本应显示 **0.7.0**。先手动备份一次，确认存档显示“可下载”；若此前为升级关闭了自动备份，再在“每日定时”设置每天的备份时间。

更新只替换备份程序并设置 `config/host.json` 中的 `backupScope: "WORLD"`，不替换游戏、采集插件和地图插件，不删除任何历史记录。替换前会保存旧程序及配置。该备份包含本机凭据，不要分享。

配置 `backupScope: "FULL"` 可明确选择旧的整服备份。配置拼写错误会拒绝启动，不会悄悄改用其他范围。手工命令行 `create` 默认也是 WORLD，旧的整服调用请加 `--scope FULL`。

## 在线备份

游戏运行时仍通过原生存档快照协议固定世界数据库文件，复制后释放快照，再压缩、校验、上传。不会直接复制正在改写的数据库，也不会把已确认采集文件重新打包。仍有磁盘读写与压缩开销，不承诺完全无性能影响。原生插件当前仍会生成采集检查点元信息，但世界备份不会读取或复制其历史数据文件。

网页只有收到完整归档并通过校验后才提供下载。“执行中”不等于已完成。备份摘要明确标记 `WORLD`，与旧整服归档区分。

## 查找存档与每日定时

备份中心按服务器分组，进入对应服务器后，分别查看“存档记录、备份任务、每日定时、恢复记录”。顶部全局范围选择某个服务器时，直接打开该服备份库；选择“所有服务器”时可以返回服务器列表。浏览器会记住最近进入的备份库。

存档每页默认 10 条，可选 25 / 50 条，按创建时间倒序。状态、手动/自动类型和日期筛选由后端处理，覆盖全部记录。日期按 UTC+8 计算，开始和结束日期当天均包含。每条显示快照时间、范围、大小及下载入口，备注、永久保留、恢复和删除放在“详情与管理”中。服务器列表显示可用存档数量、总大小与最近成功时间。

“每日定时 → 配置自动备份”可设置每天几点几分执行，例如 **03:30（UTC+8）**。时间不随浏览器或主机时区改变。今天的时间已经过去时，新计划从明天开始；任务通常在到点后约 15 秒排队。必须启用每日自动备份，且平台持续运行、执行端连接正常，才能实际制作和上传。主机离线会保留一个待执行任务；已有任务尚未结束时，不因错过多天积累多份任务。

修改每日时间会取消尚未开始的旧计划任务，已执行的任务继续完成。旧版本的间隔设置升级时转换为每日定时：有下次计划的保留该次计划，并采用它的 UTC+8 时分；没有计划的默认显示 03:00，保持原有关闭状态。保留数量、保留天数和永久保留设置不变。接口仍兼容旧客户端的间隔字段，新网页使用 `dailyTime: "HH:mm"`。

这个页面和定时方式的更新只需更新平台后刷新网页，无需再次更新游戏服程序。

## 恢复世界

下载 `.tar.gz` 后，世界位于 `server/worlds/<世界名>/`。也可以使用新版执行端的“恢复到新目录”先解压检查（需要已配置独立恢复目录）。世界备份不提供“迁移采集/创建新一期”模式，因为其中不含插件配置或缓存。

实际替换游戏世界前正常停服，另存当前世界，在游戏 `worlds` 目录放入恢复的世界文件夹，确认 `server.properties` 的 `level-name` 与文件夹名称一致，再开服检查。不要合并两个不同快照的 `db` 文件。需要的全局资源包及插件应另行保留。

文件校验和解压验证不代表已经启动真实游戏验证。此次游戏电脑需安装更新后，才能验证真实世界的在线备份全链路。
