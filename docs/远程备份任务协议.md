# 远程备份任务：中央协议

本文记录中央服务的宿主凭据、任务队列、租约、原归档续传和受限上传接口。每个执行端固定绑定一个服务器档案 UUID，不接受远程传入的本地路径、程序名或控制台命令。宿主工具 0.3.0 已接入实际执行程序并完成跨进程 HTTP 实服流程，见 [验证范围](testing.md)；管理页面和自动调度继续实施。本文的合成协议夹具单独保留，不作为实服证据。

## 身份和权限

管理员使用现有会话与 CSRF 创建执行端；每服一个固定执行端记录，重新安装时轮换凭据，历史任务保持关联。凭据格式为 `mcmhost.<hostUUID>.<随机32字节Base64URL>`，创建和轮换时仅返回一次，数据库只保存摘要。撤销与轮换会使旧凭据失效。

`/api/host/**` 使用独立的无状态鉴权链。管理员 Cookie 不能代替宿主凭据，宿主请求也不会轮换或覆盖管理员会话。Agent、采集器与宿主凭据互不通用。宿主只能读取自己的任务、维护运行实例和上传该任务的归档，不能下载游戏归档、查询玩家聊天或统计、访问管理接口。

同一执行端通过随机 `runId` 标识当前运行实例。60 秒内有心跳且未报告 STOPPED 的实例不能被另一实例接管；正常停止后可交接新实例。每次开始、续租、声明归档和发布都检查当前凭据与实例；换实例后，已经开始的旧任务进入结果不确定状态。工作进程重启沿用仍运行的本地控制程序的 runId，控制程序保持游戏和本机互斥的所有权。

## 管理接口

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET / POST | `/api/backup-hosts` | 按 serverId 筛选 / 注册固定绑定的执行端 |
| POST | `/api/backup-hosts/{id}/rotate` | 轮换凭据并解除旧实例绑定 |
| DELETE | `/api/backup-hosts/{id}` | 撤销，不删除历史任务 |
| GET | `/api/backup-jobs?serverId=&page=0&size=20` | 查询任务和结果；每页上限 100 |
| GET | `/api/backup-jobs/{id}` | 查询一个任务 |
| POST | `/api/servers/{serverId}/backup-jobs` | 创建任务：requestId、hostId、kind、note、permanent |
| POST | `/api/backup-jobs/{id}/cancel` | 取消未开始任务，或向已开始任务请求取消 |
| POST | `/api/backup-jobs/{id}/resolve` | 人工处理结果不确定任务，保留处理说明 |

创建任务复用同一 requestId 时返回原任务，关键参数不同则拒绝；FINAL 默认永久保留。创建 AUTOMATIC 类型任务本身不是定时调度，也不会自动生成后续任务。任务状态不表示游戏世界已经验证可游玩。

定期任务由 [验证范围](testing.md) 生成。任务 DTO 的 `archiveStatus` 单独描述当前归档状态；历史任务仍可为 SUCCEEDED，而归档已轮换为 DELETED，此时不再提供下载入口。

人工处理只接受 UNCERTAIN 任务，须提供 `outcome=FAILED|CANCELLED` 和非空 `note`。旧尝试随即不能发布；原始归档、未完成上传记录和本地诊断不会因此被删除。确需重新制作时另建请求，不能让不确定任务悄悄重做。

## 执行端接口

| 方法 | `/api/host/v1` 下路径 | 请求内容 |
| --- | --- | --- |
| POST | `/heartbeat` | runId、state（STARTING/RUNNING/STOPPED/ERROR）、version |
| POST | `/jobs/claim` | runId、稳定 requestId；无可领取任务返回 204 |
| GET | `/jobs/{jobId}` | 查询本执行端任务，核实超时请求的真实结果 |
| POST | `/jobs/{jobId}/start` | runId、attemptId；收到成功确认后才可开始制作 |
| POST | `/jobs/{jobId}/renew` | runId、attemptId；返回任务及取消标记 |
| POST | `/jobs/{jobId}/artifact` | runId、attemptId、sourceBackupId、sha256、bytes |
| POST | `/jobs/{jobId}/recover` | 同上，仅用于恢复同一尝试的完整原始归档 |
| PUT | `/jobs/{jobId}/content` | 原始归档字节，带 X-Host-Run、X-Backup-Attempt 和 Content-Length |
| POST | `/jobs/{jobId}/report` | runId、attemptId、outcome、固定诊断 code |

领取返回 job、attemptId、leaseUntil、active。同一领取请求只对应原尝试；旧尝试失效时 active=false，不会重新启动它。一次最多一个未结束任务；UNCERTAIN 也阻止继续领取，须先恢复原归档或明确处理。只有 RUNNING 状态的游戏执行端能领取和开始在线制作。任务租约为 120 秒，续租必须在到期前获得服务端确认；后续执行程序应持续心跳和续租。

| 状态 | 含义和处理 |
| --- | --- |
| QUEUED | 等待执行端领取 |
| CLAIMED | 尚未确认开始；过期可重新排队，旧尝试不能开始 |
| RUNNING | 已确认开始制作；过期进入 UNCERTAIN，不自动重做 |
| UPLOADING | 已登记不可替换的原始归档；允许重新上传同一份文件 |
| SUCCEEDED | 归档文件与任务结果已在同一次数据库事务内提交 |
| FAILED | 已明确失败，原诊断与尝试保留 |
| UNCERTAIN | 已开始但缺乏可靠结果，禁止自动新建第二份备份 |
| CANCELLED | 未开始时已取消，或执行端已确认取消 |

执行期间的取消请求只设置 cancelRequested；不能把尚未确认停止的执行写成已取消。轮换凭据会重新排队尚未开始的领取，已开始任务变为 UNCERTAIN；撤销还会取消未开始任务并禁止旧任务发布。

声明归档后，sourceBackupId、SHA-256 和长度不得更换，恢复上传也必须一致。若本地只剩下“已经开始”而没有可靠完整归档，执行程序必须保留诊断并报告不确定，不能用新文件冒充原尝试。中央不接受宿主直接指定成功，也不相信宿主传来的未核验摘要。

内容上传复用完整归档校验器，必须属于绑定服务器、匹配登记的原始身份和摘要，并为已确认原生刷新状态的 BDS_SAVE_QUERY 格式。接收开始、接收进度及最终发布都会复核权限；最终发布在同一事务内提交任务 SUCCEEDED 与备份 READY。压缩包校验不在全局事务锁内进行。管理员普通上传接口不能绕过宿主任务的发布约束。

上传响应丢失时先 GET 原任务；SUCCEEDED 表示已经完成，不能重新制作。普通备份记录的 `worldRuntimeVerified` 仍是 false；宿主提交文件不会自动等同于实际游戏恢复验证。

## 验证范围

迁移 V7 增加执行端、任务和领取历史；V8 增加不确定任务的处理说明。H2 与 PostgreSQL 测试覆盖独立鉴权、会话隔离、幂等、并发领取、开始前/后的过期差异、跨服拒绝、实例排他、凭据轮换/撤销、原归档恢复上传、取消和事务发布。全部原有后端用例亦通过；桌面及两种手机宽度的备份上传/下载回归通过。

`node backup/qa/verify-host-protocol.mjs` 对实际 Nginx / Java / PostgreSQL 容器执行协议往返。测试使用 **2,101,350 字节**的明确合成归档，验证超过普通 API 1 MiB 限制的宿主流式上传路由、真实容器校验、任务与归档共同完成，以及宿主不能下载归档。完成时间 `2026-10-27T08:55:55.494Z`，任务 `3f3ef0cc-059e-4b95-b8df-c1592de72c20`、备份记录 `a67d837f-aaee-474b-b736-228b89f91214`。重建后端容器后，`--check-persistence` 验证任务和归档元数据仍在。
