# 世界状态查询与离线记录

采集器 0.27.0、中央 V15 迁移和 MCP 0.3.0 提供世界状态读取。管理员在「Agent 接入」为指定服务器勾选「查询世界状态」。DSH 复用已有 MCP 连接和 OneBot 消息收发，QQ 身份查询还需要「管理 QQ 绑定」。

## 可查询内容

| 工具 | 内容 |
| --- | --- |
| `get_world_state` | 游戏时间刻数、全局雨量和雷暴量、实际已初始化的在线玩家。名单最多返回 100 人，并单独返回总数和截断标记 |
| `get_player_state` | 指定稳定玩家身份的当前维度、坐标、生命、饥饿值、背包物品类型和数量、护甲、主副手、选中槽位及游戏模式 |
| `get_qq_player_state` | 从 QQ 绑定取得角色，再执行玩家状态查询 |
| `get_last_player_snapshot` | 立即读取最近成功上传的玩家状态，标记 HISTORY 并保留原始观测时间 |
| `inspect_block` | 明确维度与坐标的方块类型和原生状态文本，可读取原版方块的朝向、红石等状态字段 |
| `inspect_container` | 已加载位置的容器槽位。熔炉、高炉和烟熏炉另有剩余燃烧刻数、燃料周期与烹饪进度 |
| `scan_nearby` | 指定坐标周围 1-8 格的方块实体及附近实体，也可按方块标识筛选。实体含位置、生命及着火/入水状态。方块和实体各最多 64 项，返回范围不完整与截断标记 |
| `get_world_query_result` | 取得本 Agent 原查询的结果或到期状态 |

物品目前返回类型和数量，护甲及主副手按各自槽位展示。物品附魔、自定义 NBT、插件外部数据和容器未来可能生成的战利品需要各自适配。

## 离线时如何回答

玩家状态在在线期间以 30 秒为目标周期分摊记录，并在离线事件里尝试采集一次。只有成功上传的观测能成为中央历史记录。每份记录保留采集端的原始时间。

玩家已经离线而服务器仍运行时，现场查询返回 PLAYER_OFFLINE，`lastKnown` 可包含之前记录的坐标和物品。玩家离线后，指定位置的熔炉和箱子仍可查询，前提是所在区块保持加载。查询会先检查加载状态，远处未加载的区块返回 CHUNK_UNLOADED。先前查过同一目标时可以附历史记录。

服务器没有响应时，查询在 30 秒后到期，返回 EXPIRED 和已有的历史记录。已知只需要离线记录时，DSH 可直接调用 `get_last_player_snapshot`，立即获得 HISTORY 或 NO_RECORD。封存档案的现场查询返回 UNAVAILABLE，已有历史仍可读。

READY 表示 `observedAt` 时的现场读取。`lastKnown.observedAt` 和 HISTORY 的时间属于历史。DSH 回答时要把时间一起说明，确认目标位置后再解释熔炉、箱子或机关的情况。

## 执行和容量

HTTP、任务领取和上传运行于独立工作线程。实际游戏对象读取由游戏线程执行，每次处理一个查询。请求类型和参数固定，世界读取权限不包含修改世界的操作。

每个 Agent 每分钟最多 30 次现场查询，每服同时最多 16 个未完成查询。容器最多返回 64 槽，结果超出上限时明确返回截断或不可用状态。快照上传每批最多 8 个玩家。每服中央缓存最多保留 10,000 个最近观测目标，达到上限后替换最早记录。玩家离线记录和已查询坐标共同使用该限额。

游戏文件备份沿用独立备份流程。世界查询的中央缓存属于平台数据库，游戏文件回档后已有观测仍带原时间。后续现场读取可更新它。

## 验证

`node collector/qa/verify-live-chat.mjs --with-world-state` 使用固定 BDS 1.26.51.1 和 LeviLamina 26.51.8 的隔离世界。通过真实客户端设置夹具，再从标准 MCP 查询实际天气、玩家背包、无燃料熔炉、燃烧熔炉、满输出槽、箱子内容和附近方块。远处未加载区块返回明确状态。原玩家离线时，另一观察客户端保持区块加载，角色返回历史数据，原位置熔炉仍能现场查询。

`npm run test:integration --prefix mcp` 对全部 23 个工具执行标准 stdio 调用，世界观测部分使用明确的协议夹具。H2 与 PostgreSQL 测试覆盖独立权限、原请求、启动身份、撤销、过期、历史顺序和缓存容量。协议测试与实服证据分别保存于项目忽略的 `.tools/`。
