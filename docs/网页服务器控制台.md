# 网页服务器控制台

管理员可通过 `/console?server=服务器UUID` 查看游戏输出、发送单行游戏命令，以及启动、正常停服和重启。服务器档案卡片和左侧导航均有入口。平台使用现有登录、管理员权限和 CSRF 校验；没有向 MCP、访客或采集器开放控制台操作。

## 接入游戏主机

使用备份中心为对应档案创建的执行端凭据，以及 `backup/host.config.example.json` 的配置格式。配置里的 `root`、`serverId` 必须与本机采集器一致；备份目录和凭据文件放在游戏目录之外。已有执行端可沿用凭据。

1. 正常停止原启动器中的游戏和原备份执行程序。
2. 配置游戏运行需要的 Python 等环境（地图 1.26.61.1 的要求见 `MAP-BDS-1.26.61.1.md`）。
3. 在游戏主机启动：

```powershell
node backup/src/console-host.mjs --config 'D:\MCManager\host.json' --start
```

不带 `--start` 时仅连接平台，等待管理员点击启动。程序必须常驻；网页停服只停止游戏，保留执行端，因此可再次启动。原 `backup/src/remote.mjs` 仍保留原行为；两个启动程序不能同时托管同一游戏目录。现有运行中的控制台不能无缝接管，首次切换需要一次正常停服。

执行端通过平台现有 HTTP(S) 地址主动同步，不新增入站端口。它会同时运行原备份工作进程，保持原备份中心功能。新模式不启动离线恢复维护程序；恢复维护仍按原流程停止控制台执行端后进行。

## 命令与生命周期

- 所有操作固定到服务器、执行端和本次连接。换服或重连后的旧请求被拒绝；不允许远程指定路径、可执行文件或操作系统脚本。
- 命令经游戏 stdin 直接发送，不经过 PowerShell、cmd 或其他 shell。换行、控制字符、直接/execute-run 的停服和备份底层命令被拒绝；停服使用网页按钮。
- 正常停服先停止备份领取与工作进程，再向游戏发送 stop 并等待退出。重启随后检查目录绑定并重新启动。不提供强杀按钮。
- “已发送”只证明写入游戏 stdin，不能证明命令成功；结果以游戏日志为准。启停完成状态根据实际进程启动握手和退出确认。
- 请求编号去重，单服同时最多一个待处理操作。未领取的操作 30 秒过期，已发出的操作 3 分钟无回执标为待核对，不自动重发；晚到的有效回执可以补全。网络恢复不会重放旧控制指令。
- 执行端在线判定为 30 秒内的心跳。凭据撤销后拒绝读取新命令；程序收到撤销结果会正常结束托管。

## 日志和存储

网页每两秒更新，执行端通常每秒同步一批，最多 100 行。平台每服保留最近 2000 行、最近 500 次操作，页面最多显示最近 30 次操作。日志来源为接入后游戏进程输出；离线时可看已收集历史。后台有界缓存满时丢弃最早日志，不承诺完整日志审计。可把执行端 stdout/stderr 重定向到本机轮换日志。

网页以纯文本显示输出，不执行 HTML/ANSI。过滤原生备份协议行、平台凭据格式和地图私有上传路径；自定义插件若自行输出其他格式的秘密，不保证自动识别，因此控制台保持管理员私有。

数据库迁移 V18 保存连接状态、日志和操作记录。新接口复用执行端身份验证，每台游戏主机只能访问自己档案的数据。
