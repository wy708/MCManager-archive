# MCP 种子推算与历史环境查询

这项能力只通过 MCP 提供使用入口，网页不新增配置页面。Agent 继续连接原有 MCP，授权 `WORLD_READ` 即可；无需新增对外端口。更新后需要在 DSH 中重启 MCP 连接，使它发现新增工具。

## 能查询什么

| 工具 | 信息来源 | 游戏服务器离线时 |
| --- | --- | --- |
| `get_terrain_prediction` | 提供种子、世界生成版本、世界类型和坐标，在平台侧计算该高度的自然群系 | 可用，不加载游戏区块 |
| `get_recorded_environment` | 已保存的方块、容器、附近环境查询结果，保留原观测时间 | 可用；没有记录则明确返回无记录 |
| `get_location_context` | 返回群系、历史记录、自然结构候选点和区块属性，四类来源分开列出 | 可用；一方暂不可用时明确标记部分结果 |
| `get_structure_predictions` | 根据种子与生成版本推算自然结构候选位置 | 可用；不代表已生成建筑实况 |
| `get_chunk_info` | 区块坐标、方块边界与基岩版史莱姆区块算法 | 可用；不需要世界种子 |

群系预测目前覆盖主世界和下界，不能生成逐方块地形、精确地表高度或建筑轮廓。新增结构候选点及史莱姆区块的范围见 [种子地图结构与区块](种子地图结构与区块.md)。不能用群系预测判断熔炉、光照和当前生物状态。超平坦、自定义世界的普通生成预测会明确返回不支持；末地不在预测范围内。实际历史查询支持三个维度。

## MCP 调用示例

调用 `get_terrain_prediction`，参数如下（`serverId` 换成 `list_servers` 返回的授权档案编号）：

```json
{
  "serverId": "d7b62efc-b9a4-4e42-9d6d-d60068539edc",
  "seed": "-9007199254740993",
  "generationVersion": "1.26.61.1",
  "worldType": "DEFAULT",
  "dimension": "minecraft:overworld",
  "x": 1000,
  "y": 64,
  "z": -2000,
  "radius": 64,
  "step": 16
}
```

以上是参数格式示例，不代表该档案实际使用这个种子或普通世界。种子必须是十进制字符串，以免大整数丢失精度；不能由 AI 猜测。版本应是查询区块的生成版本，旧区块不会因为服务端升级而自动更换生成规则。当前接受 `1.26.51.1` 和 `1.26.61.1`。`worldType` 必填，取 `DEFAULT`、`FLAT` 或 `CUSTOM`。

种子直接随工具调用传入，不保存到数据库，也不包含在响应中。平台不验证输入种子与档案实际世界是否一致，返回 `worldIdentityVerified=false`。可选的已有服务端配置仍能作为省略种子和版本时的后备来源，但不要求配置，也没有新增网页入口。

调用 `get_recorded_environment` 时传同一 `serverId`、维度、`x/y/z` 和 `radius`。它读取查询中心落在指定立方体内的最近最多 8 条观测，超出时标记 `truncated`。这里只保留每个查询目标的最近观测，不是完整的世界历史。没有记录不代表没有建筑；离线记录也不代表现在的状态。

调用 `get_location_context` 可直接使用上面的预测参数，另加可选 `historyRadius`（默认 32，范围 0–128 格）。`radius` 决定群系预测采样范围，`historyRadius` 决定历史查询范围。默认同时读取自然结构和区块属性，分别使用 `structureRadius`、`structureLimit`、`structure` 和 `chunkRadius` 参数；`includeSeedMap=false` 可只查原来的两类来源。原来的两个独立工具继续保留，输入及行为不变。

组合结果为 `COMBINED` 或 `PARTIAL`，不把不同来源合成“当前地形”。各类数据保留原始质量、限制、观测时间及截断信息；超平坦世界、未提供种子或预测服务暂不可用时，已有历史记录仍可返回。授权失败、请求取消、参数错误直接失败，不泄露其他已读取的数据；所有来源都请求失败时也返回错误。该工具目前与独立群系预测一样，支持主世界和下界。

## 性能与权限

- 种子运算在平台主机运行，不调用 BDS，不扫描游戏世界，也不会新增逐方块放置记录。
- 每次最大半径 128 格，间隔为 16、32 或 64 格，最多 289 个采样点；采样点之间没有逐格检查。
- 最多同时运行两个计算进程，计算等待上限 3 秒；重复查询使用最多 128 项的内存缓存。
- 历史查询使用服务器、维度和坐标索引，最多读取 9 行以判断截断。
- 所有相关 MCP 工具均要求该档案的 `WORLD_READ` 权限，计算完成后再次核对授权。种子通过子进程标准输入传递，不放入命令行，也不发送给第三方服务。

## 引擎与验证边界

基于 MIT 开源项目 [cubiomes-bedrock](https://github.com/FragrantResult186/cubiomes-bedrock)，固定源码提交见 `terrain/sources.json`。使用群系四格网格采样，返回 `quality=EXPERIMENTAL`。预测不能当作精确现场观测。

隔离的官方 BDS 1.26.61.1 使用 Script API `Dimension.getBiome`，在两个种子、两个维度、多个区域的 Y=64 高度取得 500 个真实观测。规范化群系别名后，499 个匹配，1 个海岸位置不匹配：种子 `-9007199254740993` 的主世界 `(-4128,64,-4064)`，实际为石岸，预测为积雪针叶林。该已知偏差保存在回归夹具中，没有隐藏或当作通过精度保证。

这不是对所有种子、高度、群系边界或旧版本的完整验证。1.26.51.1 使用独立的 26.50 生成配置，未获得与 1.26.61.1 相同的该版本实服样本覆盖。真实观测夹具是 `terrain/test/bedrock-observations.json`；MCP 的历史查询验证使用协议输入，不能当作新的游戏实测。

## 构建

```text
node scripts/build-terrain-engine.mjs
node --test terrain/test/engine.test.mjs
```

Windows 使用 LLVM clang，可通过 `MCM_LLVM_BIN` 指定工具目录；Linux 使用系统 C 编译器。构建脚本取固定源码版本，输出到忽略目录 `terrain/bin`，同时保存上游许可证。后端通过 `MCM_TERRAIN_ENGINE` 指向可执行文件；Dockerfile 包含原生引擎构建阶段。未安装引擎时返回明确的服务不可用，不伪造结果。
