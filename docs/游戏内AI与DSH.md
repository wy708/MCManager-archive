# 游戏内 `/ai` 与现有 DSH

采集插件 0.38.0 新增可选 `/ai 你的问题`，需要同步安装 `integrations/dsh` 中的 QQ 桥接适配。
默认不开启；不升级、不配置的服务器不会注册这个命令。

## 消息和记忆

游戏与 DSH/qq-bridge 位于同一台 Windows 主机。插件把问题交给本机后台线程，桥接读到后，唤醒配置的 QQ 群**现有 DSH 会话**，没有新建另一套大脑或群记忆。原人设、会话上下文、群级记忆工具继续有效，其他群和私聊仍按原规则隔离。

每次注入明确标记 `MINECRAFT_GAME`，包括真实服务器档案、稳定玩家身份、名称、维度、提问时的坐标和时间。玩家名字不是 QQ 身份证明；若需要关联 QQ，仍需已有的账号绑定流程。问题内容不能成为管理员指令。

回复复用现有 `qq_send_message` 工具的字符串 key 参数：游戏请求提供专属 `game:<UUID>` 目标与短期令牌。桥接只接受这条请求的令牌，固定回到原玩家，绝不把未知游戏目标回退成 QQ 群。令牌不能读取 QQ 记忆或操作管理接口。原群工具和权限保持不变，无需新增 MCP 服务或重置 DSH。

游戏问答进入共享 AI 上下文，因此群内的后续对话可能引用它；并非玩家私人记忆。游戏里会明确提示这一点。是否写入长期 BasicMemory 由现有 DSH 记忆策略决定，不承诺每一句都永久保存。

## 性能与限制

- 不新增公网端口、不向 平台主机 高频轮询、不为普通聊天调用 AI。
- 游戏主线程只接收短问题和发送就绪回复，文件操作和等待全在后台。
- 每人同时一个问题，间隔 20 秒；全服每分钟最多 12 个，最多 16 个未完成问题。
- 问题最多 384 个 Unicode 字符且不超过 1536 个 UTF-8 字节，回复最多 1500 个字符且不超过 6000 字节。
- 本机邮箱每秒检查一次，只扫描专用请求目录；无问题时不调用模型。一次问题最多触发三次唤醒尝试，五分钟超时。
- DSH 正在 `qq_wait_for_messages` 等待时，游戏提问会打断等待并随结果传给同一会话，不必等满五分钟。
- AI 模型本身仍消耗原 DSH 的 CPU/内存和模型额度；这是有上限的后台工作，并非零开销。
- 回复通过个人消息显示。玩家已离线则不广播、不转发到 QQ，也不在之后重启时重放。
- 返回 `queued=true, delivered=false` 表示回答已交给插件，不能宣称玩家已收到。崩溃时宁可丢弃未确认的一次回答，也不自动重复发送。

## 安装与更新

安装包包含新版采集 DLL、桥接适配模块、按版本校验的补丁程序和安装器。不包含游戏世界、聊天历史、DSH 凭据或平台密钥。

1. 正常停止游戏，关闭对应的群聊桥接窗口。无需清理 DSH 会话，也不用停止私聊桥接。
2. 编辑包内 `install.private.json`，填写 `gameRoot`、`bridgeRoot`、`serverId`、`groupId`。群必须已在桥接白名单内。
3. 运行 `node install.mjs --check`。检查包哈希、档案绑定、群白名单、补丁适用性和游戏停止状态。
4. 运行 `node install.mjs --install`。原 DLL、清单、采集配置与桥接源文件会先备份。安装保留原配置和凭据，仅增加 `gameAiEnabled: true` 与独立 `mcmanager-game-ai.json`。
5. 重新启动群聊桥接，再用原来的 `03-start.cmd` 启动游戏。输入 `/ai 你好，告诉我这条消息来自哪里`，验证只向提问玩家返回，并仍能使用原群记忆。

不要在游戏运行时覆盖 DLL。失败时不要删除整个插件或清理世界；根据安装备份恢复被修改的文件即可。旧文件继续占用或没有进程查询权限时，安装器会停止。

## 本机数据位置

`游戏目录/plugins/archive-collector/data/game-ai/requests` 与 `responses` 保存短期问题和答案。它们不是完整聊天存档；完成或过期后回收。目录依赖本机文件权限，只应让游戏服务和桥接账户访问，不应作为共享目录公开。

## 验证边界

开发验证涵盖原生 C++ 后台线程与 Node 桥接实际文件往返、多人身份隔离、并发防重、已完成答复恢复、限额和过期。编译完成不等于真实游戏与 DSH 已联调；每台服仍应按第 5 步验收，保留该群的原会话验证共享记忆。
