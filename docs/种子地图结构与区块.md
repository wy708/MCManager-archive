# MCP 种子地图：结构与区块

使用 [cubiomes-bedrock](https://github.com/FragrantResult186/cubiomes-bedrock) 的本地计算能力，向 AI 提供种子地图类工具的数据：群系、自然结构候选位置、区块边界、史莱姆区块。源码固定于 `terrain/sources.json` 中的提交，不依赖第三方网站页面或未公开接口。地图图片、逐方块高程和玩家建筑轮廓不在本功能范围内。

## 工具

- `get_structure_predictions`：自然结构候选点。输入授权服务器编号、种子字符串、区块生成版本、世界类型、维度、方块坐标 X/Z、搜索半径和数量。
- `get_chunk_info`：以方块坐标 X/Z 定位所在区块及周围区块，返回区块坐标、包含端点的方块边界、史莱姆区块标记。不接收种子。
- `get_location_context`：默认一次返回 `prediction`（群系）、`history`（实测历史）、`structures`（结构候选）、`chunks`（区块属性）。原有工具仍可单独使用。

所有工具要求档案的 `WORLD_READ`。计算和读取发生在平台侧，游戏关闭后仍可使用，不发送游戏命令或加载游戏区块。结构验证过程中使用的游戏定位命令只用于隔离验收，生产查询不调用它。

## 支持范围

| 维度 | 自然结构类型 |
| --- | --- |
| 主世界 | `village` 村庄、`desert_pyramid` 沙漠神殿、`jungle_temple` 丛林神庙、`swamp_hut` 沼泽小屋、`igloo` 雪屋、`monument` 海底神殿、`pillager_outpost` 掠夺者前哨站、`ruined_portal` 废弃传送门、`trial_chambers` 试炼密室 |
| 下界 | `fortress` 下界要塞、`bastion_remnant` 堡垒遗迹、`ruined_portal` 废弃传送门 |

`structure=all` 查询当前维度所有已支持类型，不表示 Minecraft 的所有结构都已覆盖。当前未接入末地城、要塞、古城、林地府邸等其他类型。

结构预测接受普通原版世界及 `1.26.51.1` / `1.26.61.1` 生成版本。超平坦、自定义世界返回不支持。关闭自然结构生成、旧区块、生成附加包、种子与档案不对应都会影响适用性。种子不保存、不回显，`worldIdentityVerified=false` 明确表示未核验输入与实际世界的对应关系。

## 参数例子

查询村庄的 `get_structure_predictions` 参数：

```json
{
  "serverId": "替换成 list_servers 返回的 UUID",
  "seed": "1",
  "generationVersion": "1.26.61.1",
  "worldType": "DEFAULT",
  "dimension": "minecraft:overworld",
  "x": 0,
  "z": 0,
  "structure": "village",
  "radius": 2048,
  "limit": 16
}
```

结构搜索为水平圆形，最大半径 4096 格，最多返回 32 个最近候选点。响应保留总候选数和截断标志；范围内没有候选不代表世界中没有结构。坐标是生成参考点，**不是精确入口、建筑中心、高度或完整占地**。响应提供中文结构名称、方块 X/Z、参考点区块坐标、水平距离和 `observed=false`。

区块查询的 `radius` 单位是区块，范围 0–8，默认 2，最多 289 个区块。X/Z 输入仍是方块坐标。例如 X=-1、Z=-17 属于区块 (-1,-2)，边界 X=-16…-1、Z=-32…-17。基岩版史莱姆区块算法不依赖种子，下界的 `slimeChunk=null` 表示不适用。标记为真不保证当前刷怪，仍需核对高度、空间、玩家距离和游戏规则。

综合查询保留原来的群系 `radius`（最多 128 格）、`step` 和 `historyRadius`；新增 `structureRadius`（默认 2048）、`structureLimit`（默认 16）、`structure`（默认 all）、`chunkRadius`（默认 2）。`includeSeedMap=false` 关闭本次的结构和区块查询。各来源分开返回，历史的 `observedAt` 不改为查询时间。

## 精度与实际验收

结构输出标记 `EXPERIMENTAL / SEED_PREDICTION`。算法先枚举区域生成候选，再执行上游群系筛选和可用的近似地形筛选；未读取实际世界存档，不承诺候选点一定存在建筑。

隔离的官方 BDS 1.26.61.1、种子 `1` 与 `-9007199254740993` 共进行了 23 次真实 `/locate structure` 对照：20 次返回同一区块；试炼密室有 1 次返回相邻区块的参考点（约 17 格偏移）；另外 2 次神殿候选不被定位确认：

- 种子 1，丛林神庙候选 (2728,-1928)，游戏定位返回 (3928,-1688)。
- 种子 -9007199254740993，沙漠神殿候选 (-152,376)，游戏定位返回 (-808,360)。

这些不符没有隐藏，接口限制说明和回归夹具均保留。只核对定位结果，未逐块检查结构、入口、箱子或战利品。样本不是全种子、全版本准确率证明；1.26.51.1 的该版本结构预测未进行同等实服定位验证。

史莱姆区块在 4 个不同区域共 1156 个区块与独立完整 MT19937 实现交叉核对，包含负坐标、远坐标和无符号溢出。两个支持版本的结果一致；下界为空标记。**没有把算法一致性当作游戏中自然刷怪的实测证明。**

夹具在 `terrain/test/structure-observations.json`，包含官方 BDS 文件摘要和真实定位输出；测试命令为 `node --test terrain/test/*.test.mjs`。群系原有 500 点实测回归保持不变。

## 运行开销

沿用最多两个原生计算进程和单次 3 秒时限；结构结果使用最多 128 项内存缓存。综合查询分两批读取以限制并发，缺失或不支持的来源明确标记 `PARTIAL`，权限失败和取消不会返回另一份数据。服务器历史与自然预测不是同一时刻的完整世界快照。
