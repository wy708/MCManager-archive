# 采集协议 v1

状态：中央采集服务和统计查询已实现。本文是采集器必须遵循的接口契约，不代表 LeviLamina 插件或游戏行为已经验收。

## 连接和凭据

- 服主登录后，对某份服务器档案调用 `POST /api/servers/{id}/collector-credential` 创建或轮换凭据。
- 返回的 `token` 只在这一次响应中提供；数据库仅保存 SHA-256 摘要。`GET` 同路径只返回是否配置及创建时间。
- `DELETE` 同路径立即撤销。轮换或撤销之前取得的身份，在实际提交事务内也会重新校验，不能继续提交已排队的旧凭据请求。
- 采集器使用 `Authorization: Bearer <token>`，只能访问 `/api/ingest/**`，没有管理权限。管理员 Cookie 不能代替采集凭据。
- 管理接口保留会话和 CSRF；采集接口使用独立的无状态安全链。
- 生产网络必须经 HTTPS 传输。凭据是高熵随机 Bearer token，协议没有额外的 HMAC 签名，不能在不可信的明文网络使用。

## 请求

`POST /api/ingest/v1/batches`，Content-Type 为 `application/json`。最大 1 MiB，最多 1000 个事件、64 项能力；未知 JSON 字段、重复键和整数中的小数均拒绝。

```json
{
  "protocolVersion": 1,
  "batchId": "c63f0897-72c6-440e-b745-a1054d65fc1a",
  "reportedAt": "2026-10-26T03:00:00.000Z",
  "collector": {
    "version": "0.2.0",
    "bdsVersion": "1.26.51",
    "leviLaminaVersion": "26.51.8",
    "bootId": "31ab4000-e49a-4de2-b7a7-32529f410cc4",
    "pendingEvents": 0
  },
  "capabilities": [
    {"metric":"blocks.mined","state":"ACTIVE","quality":"EXACT","algorithmVersion":"confirmed-break-v1","dimensionAware":true}
  ],
  "events": [
    {
      "eventId":"77ac8867-e322-47c9-9e9d-d44d2964883c",
      "kind":"COUNTER",
      "at":"2026-10-26T02:59:59.000Z",
      "player":{"identityType":"XUID","identity":"123456789","name":"Player"},
      "dimension":"minecraft:overworld",
      "metric":"blocks.mined",
      "subject":"minecraft:oak_log",
      "value":1
    }
  ]
}
```

时间戳必须是 1970 年后的毫秒精度 UTC 时间，事件时间不能晚于批次时间，批次时间最多超前中央服务 30 秒。历史补传不受短时签名有效期限制，发送端应先同步时钟。示例为协议示意，不是实服结果。

`events` 为空的批次可以作为当前状态心跳，报告已落盘但未确认的事件数与完整能力列表。它可以先于积压事件发送。采集器 0.20.1 每约 10 秒尝试发送新的状态快照，心跳失败时后续发送最新状态。玩家事件仍须按落盘顺序上传，相同批次重试须保留原字节。旧版已落盘的心跳仍按原顺序处理。

### 运行诊断

中央部署 V12 后可接收 `collector.diagnostics`。字段可省略，省略时诊断为未知。报告使用该次启动的 `bootId`，`sequence` 从 1 起递增，用于区分迟到补传和更新的报告。

| 字段 | 口径 |
| --- | --- |
| `queuedEvents` | 采样时还在内存队列中的事件数 |
| `rejectedSubmissions` | 本次启动队列拒绝接纳的事件数，含重试 |
| `captureGaps` | 本次启动已知的观测丢弃或失败次数，不同来源按各自的观测单位计 |
| `diskError` | 采样时写盘是否故障 |
| `diskFaults` | 本次启动发生的写盘故障阶段数，恢复后保留累计值 |
| `final` | 本次启动的最后异常摘要，随无玩家事件的批次落盘后补传 |

`pendingEvents` 继续表示已落盘但未确认的事件数。诊断不进入玩家统计。`GET /api/collectors` 返回当前运行的 `diagnostics` 与最近十次有异常记录的旧运行 `previousAnomalies`。旧运行迟到的摘要仍归原运行。

### 身份

优先使用非零、规范十进制字符串 XUID（无前导零，最多无符号 64 位），中央主键为 `xuid:<值>`。没有 XUID 时可以使用 `UUID` 类型和规范小写 UUID，主键为 `uuid:<值>`。

名字只用于显示和保存别名，不参与身份合并。较旧事件不会将当前名字改回旧名。UUID 回退与 XUID 不会因同名而自动合并；离线环境的身份对应需由后续运维规则明确处理。

### 能力

- `state`：`ACTIVE`、`DISABLED`、`UNSUPPORTED`、`ERROR`。
- 启用时必须给出 `quality`、`algorithmVersion` 和 `dimensionAware`。
- `quality`：`EXACT`、`ESTIMATED`、`OBSERVED`。移动距离和活跃时间必须为估算；最高等级允许观测最高值；其他指标不得用估算冒充精确值。
- 启用且支持维度时，事件必须包含命名空间维度。未支持维度时事件须省略维度，单维度查询不会将其当成零。
- 改变维度能力必须更换算法版本。每个版本的质量和覆盖观测时间长期保留。
- 每个新批次带完整能力列表；旧批次补传不会覆盖较新的当前能力状态。
- 覆盖时间表示曾经观测到的启用范围，不是对期间所有数据完整性的承诺；当前错误/停用状态和历史值分别保留。

## 事件

### COUNTER

字段：`eventId`、`kind`、`at`、`player`、`metric`、`value`，按能力附加 `dimension`，按分类附加 `subject`。方块必须包含类型；分类标识使用命名空间。每个增量最大十亿，SUM 指标必须大于零，MAX 指标允许零。

完整指标目录由 `GET /api/metrics` 返回。包括在线、挖掘/放置、死亡/击杀、经验、最高等级、维度、物品、动作、农业、钓鱼/繁殖/村民交易/合成、聊天和估算移动/活跃时间。

`online.millis` 和 `deaths` 只能通过专用事件写入。`level.max` 使用最大值，其余计数使用求和。伐木与矿石由挖掘方块类型分类，不另行加进挖掘总数。

聊天协议只有次数，没有正文、背包、装备、位置轨迹或插件经济等字段。

### SESSION

除公共字段外包含 `sessionId`、`startedAt`、`sequence`、`onlineMillis`、`ended`、`dimension`，不含 COUNTER 字段。

1. 开始：`sequence=0`、`onlineMillis=0`、`at=startedAt`、`ended=false`。
2. 每次检查点序号加一，累计在线毫秒数的增量必须等于相邻检查点实际经过时间，间隔不超过 24 小时。
3. 正常退出最后一个检查点设置 `ended=true`。已结束的会话不能追加新事件。
4. 每次维度切换先结算旧维度区间；检查点中的维度属于上一个检查点到本次检查点的区间。
5. 发送顺序必须保持，缺失或跳号返回 409；发送端应保留并补传前面的批次，不能跳过拒绝的数据。
6. 后端按平台时区的实际日界线拆分跨日在线；不按服务器 tick 数推算，也不在最后检查点后继续加时。
7. 同服同身份开始新会话时，旧的未结束会话按最后检查点标记 `REPLACED`，未观测到的断连区间不会凭空增加在线时长。

0.21.0 起，开始检查点可附 `sessionStart`。`JOIN` 表示采集器观察到初始化请求，并随后确认玩家已初始化。`OBSERVED` 表示开始观察时玩家已经在线，例如插件重载。旧批次省略该字段，事件哈希与旧版一致。结束检查点可附 `sessionEnd: "CAPTURE_STOPPED"`，表示采集器停止。普通离服省略该字段。新采集器应在中央升级到 V11 后部署。

0.23.0 起，`kills.mobs` 和 `kills.players` 可携带 `playerObservedAt`，表示离线归属使用的玩家身份最后一次实际观测时间。它使用 UTC 毫秒精度，不能晚于 `at`。中央以 `at` 统计死亡，用 `playerObservedAt` 更新名字历史，避免旧身份记录覆盖更新的玩家名字。省略字段时沿用原行为和事件哈希。先更新中央，再部署 0.23.0 采集器。

采集器必须周期持久化检查点，使用稳定的经过时间源生成连续时间戳。进程崩溃最多只能恢复已经落盘的进度，不能声称找回了从未保存的时间。

### DEATH

字段：公共字段、`dimension`、`cause` 和可选的命名空间 `killerType`。死亡明细和每日死亡计数在同一事务内写入。最终死因不等于完整伤害因果链，不能据此自动把环境死亡归为某个玩家击杀。

## 幂等与失败

- `batchId` 在该服内唯一。相同 ID 重试时请求体必须逐字节一致；相同 ID 不同请求体返回 409。
- `eventId` 在该服内唯一。不同批次重发同一事件只确认一次；相同事件 ID 的不同语义返回 409。
- 事件和统计连同批次收据一起事务提交。任意一个事件失败，整批不写入，修正后可以使用未提交的批次 ID 重试。
- 成功响应：`{batchId, acceptedEvents, duplicateEvents, duplicateBatch}`。接受数与重复数之和等于批次事件数。
- 采集端应先把完整批次和原始请求字节可靠落盘，收到正确 batchId 的成功收据后才能删除本地文件。网络错误、401、409 和 5xx 均不能当成已确认。
- 跨服身份与统计写入使用数据库互斥行保证事务顺序；每批大小、事件数和事务时间有限制。查询使用一致性读取，避免一次汇总混入不同提交时点的结果。

## 归档边界

事件不能早于该期开服日期。开始采集后开服日期锁定，名称和介绍仍可编辑。

封存记录独立的 `sealed_at`，修改介绍不会移动封存边界。已封存服务器可补传封存时刻之前、且不晚于结束日期的数据。不能将结束日期改为早于已经保存的数据，也不能把封存后的新游玩继续计入旧档案。

## 时区

`MCM_STATISTICS_ZONE` 默认 `Asia/Hong_Kong`，第一次接收有效采集批次后固定到数据库。之后改动环境变量不会重划历史日期，而是拒绝继续写入并明确提示恢复原配置。时区改变需要专门的数据迁移流程。
