# 大量数据补传优化 · 0.35.0

适用 Windows BDS 1.26.61.1，包含采集器 0.34.0 的全部功能。中央平台增加批量接收接口，不新增数据库迁移；MCP、地图和执行端无需随本次重复更新。

## 改了什么

- 一个请求最多携带 16 个原始批次、512 条事件，整个请求最多 1 MiB。超过组合限制的单个旧批次仍通过原接口上传。
- 采集上传复用 WinHTTP 会话和连接；网络失败后重建连接，保持证书和主机名校验，禁止重定向携带凭据。
- 待传文件在启动时建立有序索引。每次补传不再扫描、排序整个目录；追加、确认和恢复历史会同步索引。
- 新事件仍立即进入原有持久化流程，不为了凑批次而额外在内存中等待。
- 历史补录保持原顺序，实时运行状态仍可以优先上传。

## 数据如何保留

批量接口 `/api/ingest/v1/batches/bulk` 使用 `{"batches":["原始 JSON 字符串", "原始 JSON 字符串"]}`，保留原文而不是重新拼出事件批次。每个批次仍使用原编号和原内容哈希。平台后续入库优化将有界的一组批次放进同一个事务，逐条保存明细、逐批去重，全部成功后统一提交。返回值仍是按请求顺序排列的原始回执数组。

只有收到完整回执、逐一核对编号和事件数后，插件才移动对应的待传文件到 `acknowledged`。回执丢失、格式错误、批次中途失败时保留原文件；下次重复上传由平台去重。整组提交失败时，这一组的新写入会一起回滚；客户端可回退逐批发送。对升级前已经部分提交的批次，重试仍按原编号去重，不会重复增加统计。

遇到旧平台或批量请求失败，会暂时退回单批发送，保持已有安装兼容。损坏的队首文件不会被静默跳过；有效前序批次可以先完成。不要运行两份采集器、不要手动更改正在使用的缓存目录。

## 已有游戏服更新

1. 先部署支持批量接收的中央平台。
2. 游戏中有人时，可以先下载更新包到独立目录；等正常停服并确认游戏进程退出后再覆盖。
3. 解压 `MCManager-Collector-1.26.61.1-0.35.0.zip`，把 `plugins` 合并到游戏目录，例如 `E:\bedrock-server-1.26.61.1`。
4. 仅覆盖 `plugins\archive-collector\archive-collector.dll` 和 `manifest.json`，保留 `config`、`data`、游戏世界和其他插件。
5. 按原方式启动，确认采集器版本为 0.35.0。原来积压的数据会自动继续补传，不需要重新绑定服务器。

更新包应放到游戏目录，不是放到包含 `03-start.cmd` 的执行端目录。已有服务器不需要重跑完整安装包。本次不修改执行端程序或其校验清单。

## 验证与性能边界

- `TelemetryIntegrationTest` 覆盖原文哈希、重复批次、会话顺序、部分提交重试、凭据撤销和请求大小限制。
- 原生核心测试覆盖缓存顺序、重启恢复、组合大小、超大单批回退、损坏文件和确认幂等。
- `scripts/verify-replay-upload.mjs` 使用真实 WinHTTP、持久化文件和 PostgreSQL；模拟回执丢失、缺项、乱序、错误计数、502 和旧平台 404。传入隔离 QA 游戏目录时，还会加载真实 BDS 1.26.61.1 补传旧格式文件并检查运行采样。
- 速度测试给请求额外增加固定延迟，以比较单批与组合发送的请求开销；结果不是公网吞吐承诺。大事件、磁盘速度、网络状况和平台处理时间仍会影响完成时间。

运行集成验证需要本地 Docker、Java 21、已构建的后端和原生测试程序。输出目录必须不存在；测试使用独立数据库与临时凭据，不能指向真实游戏服目录。

## 平台入库优化（2026-11-08，继续兼容插件 0.35.0）

- 一组最多 16 批、512 条事件，合并为一次数据库提交；保持同步落盘与原来的 30 秒事务超时。
- 事务内一次读取已有统计覆盖范围，仅在最早/最晚时间真正改变时更新；算法版本和维度一致性仍检查，回滚后缓存也随事务丢弃。
- 同一事务里汇总玩家最早/最后出现时间、所有曾用名及各名字的观测时间；并保留相同观测时间时后到名称的既有规则。外键所需记录在首次事件前建立。
- 每条行为明细、原始事件哈希、坐标、聊天原文、容器变化、会话顺序、施工贡献和运行采样继续保存；没有合并或抽样删除查询明细。
- 数据库的同步提交、日志持久化和完整页保护保持开启。

新增测试对照逐批/整组入库后的逻辑数据，覆盖跨天会话、名字变化与迟到记录、方块坐标、聊天、死亡、箱子变化及去重；`scripts/verify-ingest-parity.mjs` 用相同原始字节对照上一版与新版后端，并核对 PostgreSQL 查询数据和动态记录顺序。回滚、旧批次重传和 0.35.0 原生上传通道另行验证。

此次只需更新平台后端。已经使用 0.35.0 的游戏服无需再覆盖插件或重启，MCP 和地图也无需更新。
